Before and after

Before: Fast decoding under an explicit buffer proof: The base already had table decoding, a fast path, two literal decoding and 8-byte copies. This PR specializes and removes checks from that path rather than introducing streaming DEFLATE. Fast-loop exits preserve the incremental decoder: The old fast path returned a boolean and stopped before exceptional work. CPU-gated CRC folding with a table tail: CRC-32 used slice-by-8 tables already; the old module comment incorrectly described one table lookup per byte. Separate replay equivalence from warm-process timing: One differential run was used for update timing as well as semantic equivalence, and the two fanout entries were smaller. After: Fast decoding under an explicit buffer proof: The head uses 10-bit literal and 8-bit distance roots, packed flags/skip/take entries, pointer refills, a third root literal, and 8/16-byte match copies. Fast-loop exits preserve the incremental decoder: Three explicit outcomes distinguish block end, normal handoff and pending-distance handoff while leaving the public step and limit contract in place. CPU-gated CRC folding with a table tail: x86-64 pclmul and AArch64 aes/PMULL kernels fold 64 or 128 bytes per step. Other targets or missing CPU features use the existing table algorithm. Separate replay equivalence from warm-process timing: The checker detects differential rows, skips only the update-us limit for that mode, still requires differences=0, and CI runs the same short stdlib replay again without --differential for timing.

3. Understand CRC dispatch and folding · Deep dive

Four accumulators become eight at 512 bytes

The first 64 bytes seed four lanes. At least 448 remaining bytes select eight lanes, so the wide path begins at 512 bytes. FOLD_128 advances lanes in 128-byte groups, then FOLD_64 merges eight lanes into four and FOLD_16 collapses to one block. Table processing reduces that block and the final tail.
