Purpose and review path

Observed

This snapshot adds a parallel client compilation path: shared template parsing feeds a Vapor IR and DOM-oriented code generation. The generated program creates real DOM blocks and registers reactive work with runtime-vapor. Existing VDOM rendering remains a separate path.

Review the IR before individual directives, then cross the generated-helper boundary into the runtime. Finally inspect shared runtime-core/runtime-dom changes for assumptions about renderer-specific fields.

The representation is the contract

Observed

Static HTML, dynamic references, operations, effects and return nodes are separate IR concerns. A static template index names a factory; a dynamic node ID names a generated variable. The generated child traversal depends on which IR children are absent from the template. Those identities must remain consistent when a transform wraps, removes or inserts a node.

Proposed

An expression-only feature may belong entirely in expression codegen; a new runtime abstraction is unnecessary when the existing Block contract suffices.

Compiler design

Transform and codegen invariants

  • Why are DOM navigation references emitted before insertion operations?
Read detailed explanation (3 sections)

Entry and exit order

Observed

compile combines the base preset with supplied transforms. Entry transforms run in order; exit callbacks run in reverse. Structural transforms create nested blocks and restore the previous template/dynamic/slot state on exit. Review code that mutates context.node with this stack discipline in mind: removal short-circuits later work, while replacement changes what later transforms see.

Sources: packages/compiler-vapor/src/compile.ts:76–99 · packages/compiler-vapor/src/transform.ts:208–267 · packages/compiler-vapor/src/transform.ts:100–166

Creation precedes reactive work

Observed

genBlockContent emits instantiated templates and DOM navigation variables before ordinary operations and effects. genEffects can group multiple IR effects inside one renderEffect wrapper after processing expressions. Constants, v-once and static binding metadata can move an operation out of reactive work. The invariant is preservation of dependencies and creation order, not an effect per directive.

Branch and list ownership

  • What survives a branch switch, and what is disposed?
  • How are reused item blocks updated without rebuilding their DOM?
Read detailed explanation (3 sections)

Conditional identity and disposal

Observed

A DynamicFragment keeps an anchor, current key, nodes and an optional scope. Equal keys return without rebuilding. A changed key stops the previous scope, removes its nodes, creates the next scope and inserts new nodes before the anchor. Fallback rendering uses the same ownership area when the selected block is invalid. The stable anchor is the position; the key is the identity; the scope is the lifetime.

Sources: packages/runtime-vapor/src/block.ts:12–78 · packages/runtime-vapor/src/apiCreateIf.ts:10–37

Keyed list reuse

Observed

ForBlock holds DOM nodes, an optional item scope, render key and shallow refs for item/key/index. The runtime distinguishes unkeyed positional reuse from keyed matching. In the unknown keyed region it maps keys to new positions, updates retained blocks, removes missing ones and computes a longest stable subsequence only when movement is detected. Reverse insertion supplies an already-known next anchor.

Sources: packages/runtime-vapor/src/apiCreateFor.ts:68–143 · packages/runtime-vapor/src/apiCreateFor.ts:206–296 · packages/runtime-vapor/src/apiCreateFor.ts:299–380

Optimization proof obligations

Proposed

Compiler flags encode once/static, component item and only-child information. Component items already own scopes; FAST_REMOVE may clear the parent container. A reviewer should verify the flag producer and consumer together and test emptying/refilling, reordering, duplicate identities and removal while an effect is queued. These are proposed checks, not claims that all such cases are covered.

Reconstructed internal contract

Observed

RawProps contains named getter functions and an optional dollar array of dynamic object sources/getter maps. Declared props are lazily read by proxy, with camelized lookup and shared resolvePropValue casting/defaults. Dynamic sources are scanned from last to first for ordinary values. Attr and event separation

Observed

Attrs exclude declared props and emit listeners. Class/style have merging behavior across sources, unlike ordinary last-source resolution. The interop attribute test checks that an emit handler does not also fall through to the native VDOM child and fire twice.

Slot resolution and fallback

Observed

RawSlots provides static BlockFn entries and optional dynamic sources. createSlot uses raw-props proxy semantics for slot props, caches a bound function on a resolved slot, and uses DynamicFragment for replacement/fallback. Dynamic slot names or sources install a renderEffect; static selection can run once. Stable identity prevents a slot from being reconstructed for an unchanged selection.

Sources: packages/runtime-vapor/src/componentSlots.ts:62–159 · packages/runtime-vapor/src/block.ts:12–78

Template refs are post-flush resources

Observed

createTemplateRefSetter captures its owner. Dynamic refs unset the prior string/ref, then schedule the new value; v-for values collect in arrays. Scope disposal clears values or removes an item. Function refs are invoked through error handling. The source flags repeated scope-disposal registration for dynamic refs as TODO, so lifetime review is warranted.

Conversions belong at specific layers

Observed

setText expects an already converted string, whereas setElementText converts unknown values. setHtml assigns innerHTML directly; neither that helper nor the generated operation is evidence of a sanitizer. Property setters handle nullish coercion and failures; attribute setters remove nullish values. Review the helper selected by the generator with these preconditions.

Reconcile removed keys and registrations

Observed

Dynamic prop updates merge sources, clear keys missing from the next object and then set current values. Event values use the effect-cleanup listener route. Delegated events instead store node handlers and share a document listener. The delegated handler walks composed-path/ancestor nodes and observes cancelBubble. These mechanisms have distinct cleanup/replacement assumptions.

Observed

Proposed

Adopt rather than clone

Observed

The SSR-app entry runs create/mount within withHydration. Factories adopt currentHydrationNode, and direct node insertion is skipped. Initial insertion state points at the first child; later helpers derive the cursor from parent/anchor state. This couples generated static shape to server DOM identity.

Fragment matching and limitations

Proposed

Cursor location can search backward from a closing fragment comment and cache its opening partner. Adoption skips comments when needed, performs limited dev shape checks and advances to the next node. Mismatches warn, with explicit TODO recovery/diagnostic work. Proposed review should test nested empty fragments, wrong shape, missing nodes and state restoration after errors.

Suggested passes

Proposed

  1. Establish representation: compiler entry, IR, transforms and block codegen.
  2. Trace runtime lifetime: template factories, blocks, renderEffect, scope and scheduler.
  3. Review component contracts: props/attrs/emits, slots, refs and lifecycle.
  4. Review SFC integration, each interop direction and hydration.
  5. Inspect shared runtime/compiler compatibility, exports, build trimming and test configuration.

This order is proposed to reduce context switching. The complete file inventory stays available so architectural grouping does not erase supporting or omitted files.
