1. A call has 31 input bytes remaining and 320 output bytes available. What should the optimized decoder do?

Correct answer: Leave this work to the unit path because FAST_INPUT requires 32 bytes.

The fast loop requires both windows. Falling short is a normal handoff; the public decoder can continue incrementally.

3. Why does a match distance of 8–15 use ordered 8-byte copies rather than the general 16-byte copy?

Correct answer: The following piece may need bytes produced by the preceding piece.

LZ matches can overlap. The code uses pieces no larger than the safe copy distance, with separate handling for very short periods.

5. When can the eight-accumulator CRC path first be selected?

Correct answer: At 512 bytes total, including the initial 64 bytes.

The first 64 bytes are consumed before comparing rest.length with FOLD_WIDE_MINIMUM = 448. Hence the first eligible prefix is 512 bytes.

6. A step produced bytes but gzip trailer validation later fails. How should a caller treat those bytes?

Correct answer: Discard the stream output; it is not verified until Finished.

Buffer safety and stream integrity are different obligations. The public API explicitly states that output is provisional until Finished and must be discarded after failure.
